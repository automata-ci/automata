# Embedded SSR artifacts

Automata executes the Vite server bundle as a WASI Preview 2 component. The
component and Vite client assets in
`../../crates/automata-ci-ui-renderer/assets/` are generated, hash-addressed,
checked into Git, and embedded by `automata-ci-ui-renderer`. Cargo never runs
npm, downloads JavaScript tooling, or generates these files implicitly.

The component boundary is deliberately narrow:

```wit
package automata:ui@1.0.0;

world renderer {
    export render: func(request: string) -> string;
}
```

The authoritative WIT file lives at
`../../crates/automata-ci-ui-renderer/wit/renderer.wit`. The host gives the guest
no inherited filesystem, sockets, environment, arguments, stdin, stdout, or
stderr. It creates a fresh store and component instance for every request and
enforces input, output, memory, table, instance, host-resource, fuel,
concurrency, and wall-time limits.

## Regeneration

Regenerate only inside the locked `ubuntu-24.04` runner profile. The profile
pins Rust 1.97.1 with the `wasm32-wasip2` target, Node.js 24.19.0,
`wasm-rquickjs-cli` 0.4.1, `cargo-cyclonedx` 0.5.9, `cargo-deny` 0.20.2, and the
exact Clang/libclang 18.1.3 Ubuntu packages. It also installs the official WASI
SDK 24.0 x86_64 Linux archive at `/opt/wasi-sdk-24.0` only after verifying
SHA-256
`c6c38aab56e5de88adf6c1ebc9c3ae8da72f88ec2b656fb024eda8d4167a0bc5`.

Use the profile launcher for both local and GitHub-hosted reproduction:

```console
scripts/ui/reproduce-renderer-in-profile.sh
```

When already inside that profile, the launcher runs the shell contract tests,
the low-level generator, and the dependency-policy audit directly. Otherwise it
validates the checked manifest and lock hashes, resolves only the exact
digest-pinned GHCR image, and bind-mounts the checkout at the normal
`/__w/automata/automata` path. It never falls back to the ambient hosted-runner
toolchain or rebuilds an unpinned substitute. The generated bytes do not depend
on the checkout's absolute host path. The locked image must therefore be
published before a fresh GitHub-hosted runner can execute this gate.

The script uses `npm ci`, builds both Vite targets, generates a temporary
wasm-rquickjs wrapper, replaces its general-purpose dependency declaration and
resolution with the reviewed `wrapper.Cargo.toml` and `wrapper.Cargo.lock`, and
builds with exactly:

```console
cargo build --locked --release --target wasm32-wasip2 \
  --no-default-features --features p2,encoding
```

The reviewed manifest exposes only the `p2` and `encoding` features and pins the
18 direct dependencies used by that profile. This prevents unused optional
crypto, SQLite, Preview 3, and git-patched packages from entering the lockfile,
SBOM, or dependency-policy audit. A narrowly vendored `rquickjs-macro` patch
uses insertion-ordered collections when emitting tokens, removing upstream
clean-build nondeterminism; its complete source tree is bound into provenance.
`rquickjs-sys` 0.10.0 cannot use its bundled WASI bindings because their
32-bit ABI assertions are invalid, so it generates bindings during the build.
The regeneration preflight rejects ambient bindgen, Clang, WASI SDK, C/C++
compiler, archiver, Rust wrapper/flag, Cargo target/profile/source, and Cargo
configuration overrides before it creates scratch or changes generated
outputs. It then validates and supplies only the fixed libclang, Clang, and
`WASI_SDK=/opt/wasi-sdk-24.0` paths to the wrapper build. Consequently
`rquickjs-sys` never takes its unauthenticated SDK download fallback. The exact
packages, SDK archive identity, compiler versions, and installation root are
recorded in provenance.
The large generated wrapper source is
intentionally not committed. A candidate is generated, receives a byte-checked
copy of the reviewed macro patch beneath its own Cargo workspace, and is
compared with the stable, ignored `target/ui-renderer-wrapper/source` tree; the
stable tree is replaced only when its content changes. Keeping the path-patched
crate beneath the wrapper workspace makes Cargo's package identity independent
of the checkout's absolute path. Regeneration rejects any source-less Cargo
package whose manifest escapes that workspace, preventing future path patches
from restoring the same hidden absolute-path input. Builds also use one codegen
unit, disabled incremental compilation, a fixed `SOURCE_DATE_EPOCH`, and a
complete Rust and C path remap for the repository, Cargo home, and Rustup home.
The WASI SDK root is remapped as `/wasi-sdk` as well. `PROVENANCE.toml` records
tool and SDK identities, source-bundle, manifest, lockfile, WIT, public-path,
and artifact hashes. `renderer.cdx.json` inventories the Rust
dependency graph compiled into the component and binds it to the component's
SHA-256 digest. The component also carries the WIT SHA-256 in a deterministic
custom section, so changing only the external provenance cannot make a stale
component appear current. Review both like any other executable dependency.

Verification is offline and does not rebuild anything:

```console
scripts/ui/verify-renderer-assets.sh
```

After regeneration, audit the selected wrapper graph with the repository policy:

```console
cargo deny --manifest-path target/ui-renderer-wrapper/source/Cargo.toml \
  --locked --config deny.toml check advisories bans licenses sources
```
